# 独立性审计：M4/M5 的高分究竟证明了什么

本文件的目的是**主动披露**本轮设计的机制重叠，使 `M4 = M5 = 1.0` 不被误读为
视觉场景 grounding 能力。这是本轮必须如实写明的限制，不是可修掉的工程缺陷。

## 1. 已经解决的问题：v2 的词法同义反复

v2 的候选文本含机动方向词，真值与预测由同一个方向词经词法产生。
纯词法基线 M_LEX 达到与 M4/M5 相同的 1.0。证据 `diagnosis/LEXICAL_SUFFICIENCY.json`。

v3 实测（`results/*_ANALYSIS.json` 的 `tautology_check`）：

| 切分 | M_LEX 平衡正确率 | M_LEX 覆盖率 | `lexically_tautological` |
|---|---|---|---|
| DEV | 0.0 | 0.0 | false |
| HIST | 0.0 | 0.0 | false |

M_LEX 在全部 176 样本上返回 `UNKNOWN`，reason code
`LEXICAL_DIRECTION_UNRESOLVED_BY_CANDIDATE_TEXT`。词法充分性已被打破：
候选文本里不再有任何可读出答案的方向词。

`diagnosis/DESIGN_CHECK.json` 的 C2 进一步证明真值不再是文本对的函数——
`CFG_LONGER_VS_STRAIGHTER` 与 `CFG_LONGER_VS_SHARPER` 这两个**固定**配置
在不同布局上同时出现 `TASK_EQUIVALENT` 与 `TASK_DIVERGENT`。

## 2. 仍然存在的机制重叠

真值被定义为**允许输入的函数**：两候选指代表达在该布局公开 OpenDRIVE 上
解析到的 (分支, 执行位置) 元组是否相等。因此原则上存在一个正确实现能够答对全部样本。
M4 实现了这样一个解析器，于是得到 1.0。

方法侧与标注侧共同依赖的事实：

| 事实 | 方法侧读取路径 | 标注侧读取路径 | 是否同源 |
|---|---|---|---|
| 后继道路长度 | `taskstructure.branch_attributes` 读 `road/@length` | `labels._measure_branches` 读 `road/@length` | **是（同一 XML 属性）** |
| 连接器转向幅度 | 车道中心线采样 `topology.lane_center_at` 首尾切向差 | `planView/geometry/@hdg` 首尾差 + arc 曲率修正 | 同一几何事实，**不同量法** |
| 分支 semantic_role | 公开拓扑 `branch_connections` | 同 | **是** |
| 执行位置序数 | `taskstructure` 自带序数词表 | `labels._ORDINAL_WORDS` 独立词表 | 同一词，独立实现 |

已做的隔离：
- `labels.py` 不 import `methods.py` / `taskstructure.py` / `referring.py`，不读任何方法输出。
  `full_relation_function_called: false`、`method_output_read: false` 逐行记录。
- 两侧解析器**分开书写**：方法侧用正则表面形式表 + 车道中心线采样；
  标注侧用短语包含判断 + planView hdg。二者缺陷不共享。
- 实测一致性 132/132（`DESIGN_CHECK.json` 的 C4）。这是**一致性证据**，
  同时也正是重叠的度量：两套独立实现算出同一答案，说明该答案由公开地图唯一确定。

## 3. 因此 M4/M5 的 1.0 表示什么、不表示什么

**表示**：给定候选指代表达与公开地图，本轮实现的运行时任务结构投影能够
正确判定任务关系；两套独立编写的解析器在 22 个真实布局上互相验证。

**不表示**：
- 不表示从 RGB 观测落地对象的能力。M4 完全不读 RGB。
- 不表示 M5 的候选未来有增量价值。M5 vs M4 差值 **0.0**（两切分均如此）。
  按融合规则拓扑为主证据，候选未来虽被无条件计算并计入代价，但未改变任何判定。
- 不表示部署性能。M6 特权参考同样 1.0，与 M4/M5 无法区分。

## 4. 本轮真正的经验性发现在 M3

M3 只读同观测候选短期轨迹，是唯一依赖 VLA 实际语言落地行为的非特权方法。
它的结果不是由构造决定的，而是实测的：

| 切分 | M3 平衡正确率 | 正确判等价 | 正确判分歧 | 分歧误判为等价 | 等价误判为分歧 |
|---|---|---|---|---|---|
| DEV | 0.5469 | 31 / 32 | 2 / 16 | 14 | 1 |
| HIST | 0.5000 | 42 / 56 | 7 / 28 | 21 | 14 |

M3 并非"全部判等价"：两切分都同时存在漏判与误判。它之所以停在近乎随机的水平，
是因为**轨迹差异与任务关系统计独立**。HIST 上这一点是精确的：

| HIST 子集 | 样本数 | 其中真实分歧 | 占比 |
|---|---|---|---|
| 轨迹不同（> 0.10 m） | 21 | 7 | **0.333** |
| 轨迹接近（≤ 0.10 m） | 63 | 21 | **0.333** |
| 全体基线率 | 84 | 28 | **0.333** |

三个比例完全相等：知道两候选轨迹是否不同，对判断任务关系不提供任何信息。
DEV 上轨迹不同的样本只有 3 个（其中 2 个真分歧），样本量太小不足以支撑相反结论。

含义：冻结 SimLingo 确实对不同候选文本产生了不同的 2.5 s 轨迹
（HIST 上 21/84 超过 0.10 m 阈值），但这些差异**与候选指代的分支无关**——
轨迹变了，却不是朝着"通向更长那条路的出口"或"连接车道弯度最小的出口"
所指的那个分支变。这是关于该 VLA 是否落地公开地图属性指代表达的**真实否定结果**，
按 §11 保留，不通过调阈值、删样本或换布局"解除"。
阈值 0.10 m 是在 DEV 上按事先固定网格与并列规则选出的，不是为这个结论挑的。

## 5. 若要检验视觉 grounding，需要什么

需要真值取决于**只能从 RGB 得到**的事实：场景中放置可指代对象
（如两辆白车分别停在不同路口），候选只差指代哪一个对象，
标注侧从场景规格知道对象与路口的绑定，方法侧必须从 RGB 恢复。
这要求新的 CARLA 采集（放置对象、原生 Ubuntu + 本地物理显示器），本轮预算内未完成。
`R_UNRESOLVABLE_APPEARANCE` 子集是该方向的最小前置检验：
它确认了当所需属性不在允许输入内时，M4 会如实报 UNKNOWN（16/16、28/28），
而 M3 会给出错误的确定判断（16/16、28/28）。
